# AutoResearch handoff and compatibility

This reference is shared by PaperNexus research and locally installed AutoResearch clients. It does not replace their scientific state machine or strict acceptance lints.

PaperNexus owns source/provenance and import readiness. AutoResearch owns project phases, candidate decisions, experiment intent and claim promotion. Transfer a packet reference and source versions instead of independently rewriting equivalent completed flags in multiple files.

Before fresh acquisition, reuse compatible discovery packets, selected-paper ledger, graph import status and source reading spans. Revalidate when source content, graph revision, quality version, evidence role or candidate mechanism changes. A quick standalone question does not start the full AutoResearch pre-idea gate. A selected deep AutoResearch idea still obeys its reading, breadth, protocol and evidence lints.

On new servers prefer the three research tools and capabilities/summary. Where an advanced operation is required, feature-detect the advertised legacy schema or select all/legacy profile; silently ignored fields are not evidence of support. Track asynchronous IDs; do not rerun imports after ambiguous timeout.

The caller must generate action slates before proposal_graph_session. Read advanced.md for concrete input and commit constraints. A server returning needs_actions has not generated an idea. Do not provide only evidenceRefs then wait for a committed result. Server outputDir and local `.autoreskill/` are different filesystems; materialize returned artifacts locally before local lints.

Literature review owns the source/protocol matrix; innovation owns candidate evidence and collision questions; the ideation panel owns independent causal-hypothesis review. Reuse the same evidence IDs. Select one main generator (caller actions or research_controller); avoid serially repeating three generation loops. Negative or absent evidence remains bounded by query coverage and provider failures.

Suggested session index: corpus, capability contract, question, depth, source/evidence refs, graph/source/quality revisions, pending run/job/task IDs, selected candidate IDs, unresolved evidence and next operation. This is a handoff index, not a new completion authority or an instruction to overwrite existing StateStore records.

Install the shared bundle and managed adapter with `scripts/install-research-skills.py` from the repository; preview is the default and apply requires a fresh backup directory. See `docs/operations/research-release-runbook.md` in the checkout for exact commands and recovery.
